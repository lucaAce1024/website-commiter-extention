# PRD：Trends 挖词（Side Panel 新 Tab）

| 文档版本 | 日期 | 说明 |
|---------|------|------|
| v0.1 | 2026-04-08 | 初稿：需求规划与实现边界 |

---

## 1. 概述

### 1.1 背景

在 Chrome 插件 **外链提交助手** 的 Side Panel 中新增一个模式 Tab，命名为 **「Trends挖词」**。用户输入 **词根** 与 **参考词**，基于搜索引擎 Trends 数据识别 **持续上升** 的查询词，并通过 **多轮迭代请求** 自动拓展 **长尾词** 集合，用于 SEO / 投放拓词等场景。

### 1.2 设计参照

交互与信息架构对齐用户提供的 **「新词挖掘机」** 类界面（单列表单 + 参数区 + 主操作 + 进度与历史），以降低学习成本：

- 顶部：模式 Tab 中新增一项「Trends挖词」。
- 中部：词根、参考词、时间范围、阈值、上限等配置。
- 底部：开始 / 停止、下载、运行状态、**搜索 / 任务历史**。

### 1.3 目标用户

- 需要基于 **趋势强度** 筛词的内容与 SEO 从业者。
- 希望在 **可控轮次与规模** 下自动拉长尾、减少手工复制 Trends 页面操作的用户。

### 1.4 成功标准（可验收）

1. 用户能输入词根与参考词，启动任务后，系统能列出 **上升趋势满足阈值** 的词（见第 3 节精确定义）。
2. 任务支持 **自动进入下一轮**：将本轮合格词作为下一轮的「待探测词」，持续请求直至达到 **轮次 / 数量 / 手动停止** 等终止条件。
3. 结果可 **导出**（如 CSV/JSON），历史记录可回看 **参数、时间、成功/失败**。

## 2. 名词与字段定义

| 名称 | 含义 | 与参照界面对应关系 |
|------|------|-------------------|
| **词根** | 多行输入，每行一个词根或种子短语；是 **拓展与请求的起点集合** | 类似「种子关键词」 |
| **参考词** | 单条或多条（产品可二选一：单行主参考词 + 可选多行辅助）；用于 **对比或归一化**（如相对热度、品类锚点） | 类似「基准关键词」 |
| **上升趋势** | 数据源提供的「相对上一周期变化」或「Breakout / Rising 分数」；PRD 要求可映射为数值并与阈值比较 | 对应 Trends「上升」相关指标 |
| **轮次** | 第 1 轮用词根集合请求；第 N+1 轮用第 N 轮 **通过筛选** 的词集合（可配置是否合并词根） | — |
| **长尾拓展** | 通过多轮迭代，从短词/词根逐步得到 **更长、更具体的查询** | 业务目标 |

## 3. 核心业务规则

### 3.1 筛选条件：上升趋势大于 100%（> 1）

**需求原文**：筛选出上升趋势 **大于 1（即大于 100%）** 的词。

**产品定义（需实现时与数据源字段对齐）**：

- 若数据源提供 **百分比变化**（如 `+150%`）：则保留 **严格大于 100%** 的项（即增幅 > 100%）。
- 若数据源提供 **归一化指数**（如 0～2，其中 1 表示持平）：则保留 **> 1** 的项。
- 若数据源仅有 **分档**（如 Breakout / Rising）：需在技术方案中 **约定映射规则**（例如仅保留 Rising 且数值档位于 Top 区间），并在 UI 上以文案说明，避免与用户理解的「100%」不一致。

**默认推荐**：优先采用可 **数值化比较** 的字段；在 UI 上展示「当前数据源指标名称 + 阈值含义」，减少歧义。

### 3.2 多轮持续请求（迭代拓词）

**流程概要**：

1. **初始化**：将用户输入的 **词根** 去重、trim 后作为 **第 1 轮队列**；**参考词**参与每次请求的参数（见实现方案）。
2. **单轮处理**（可对队列内词 **串行或限并发**）：
   - 对每个待探测词发起 Trends **相关查询 / 上升查询** 请求（具体 API 或页面解析由技术选型决定）。
   - 对返回列表应用 **3.1 筛选**。
   - 将合格词进入 **结果集**（全局去重）。
3. **下一轮**：
   - 将 **本轮合格词**（可配置是否排除已作为种子探测过的词）作为 **下一轮队列**。
   - 重复直至触发 **终止条件**。

**终止条件（建议全部支持配置）**：

- 达到 **最大轮次**（如 3、5、10）。
- 达到 **累计合格词数量上限** 或 **单轮请求词数上限**（与参照 UI「关键词上限」一致）。
- 本轮 **无新增合格词**（可选：连续 K 轮无增量则停止）。
- 用户点击 **停止**。
- 错误熔断：连续失败次数、总超时（可选）。

### 3.3 长尾拓展策略（逻辑要求）

- **拓展来源**：每一轮的新增合格词作为下一轮的「种子」，形成 **广度优先式** 的拓词树（可选：深度限制，避免无限向同一分支钻取）。
- **去重与规范化**：
  - 全局对 **小写 / 全半角 / 多余空格** 归一化后再去重。
  - 可选：**与参考词的语义去重**（若后续接 LLM，可作为 v2；MVP 可不做）。
- **与参考词的关系**（需在技术方案二选一或做成选项）：
  - **对比模式**：参考词仅用于 UI 展示或同一图表对比，筛选仍基于各候选词自身上升趋势。
  - **相对模式**：仅保留「相对参考词上升幅度」超过阈值的词（若数据源支持）。

## 4. 功能需求（按模块）

### 4.1 表单与参数

| 控件 | 说明 | 校验 |
|------|------|------|
| 词根 | 多行文本，每行一个词 | 至少 1 行非空 |
| 参考词 | 单行或多行（与产品最终稿一致） | 至少 1 个（若采用「必选参考」） |
| 时间范围 | 下拉：如过去 7/30/90 天、过去 12 个月等 | 与数据源能力一致 |
| 地理 / 语言 | 可选：国家/地区、界面语言 | 若 Trends 数据源支持 |
| 上升阈值 | 默认对应「>100%」或「>1」 | 数值合法范围提示 |
| 关键词上限 | 累计保存的合格词或总请求词数达上限即停止并提示 | 正整数 |
| 最大轮次 | 控制迭代深度 | 正整数，默认如 5 |

### 4.2 操作

- **开始采集**：校验通过后启动后台任务（Service Worker / Offscreen / 专用 Tab 等由开发定）。
- **停止**：中断队列与网络请求，状态置为「已停止」，保留已得结果。
- **下载实时数据 / 导出**：导出当前结果集（文件名含时间戳）；若任务进行中，导出**截至目前**的快照。

### 4.3 状态与反馈

- 展示：**当前轮次**、**已请求词数**、**累计合格词数**、**最近错误信息**（若有）。
- 订阅/配额提示：若产品存在免费额度（参照截图），在 PRD 层保留 **额度与升级引导** 占位，具体数字由运营配置。

### 4.4 搜索历史 / 任务历史

每条记录建议包含：

- 时间戳  
- 词根摘要、参考词摘要  
- 时间范围  
- 状态：成功 / 失败 / 已停止  
- 可选：导出链接或本地存储 key  

失败时记录 **失败原因**（网络、解析失败、配额、用户取消等）。

### 4.5 与现有插件集成

- 在 `sidepanel.html` 的 `mode-tabs` 中增加 `data-mode="trends"`（或约定命名），对应独立 `mode-panel` 区域。
- 样式与现有 `section` / `btn` 规范一致，避免独立一套视觉。
- **权限**：若需访问 `https://trends.google.com` 或第三方 API，在 `manifest.json` 中声明 `host_permissions`；若仅走自建后端，则改为 `https://your-api/*`。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单轮内可配置并发上限，避免被封禁；请求间隔（throttle）可配置 |
| 稳定性 | 单词失败不拖垮整轮；记录日志便于复盘 |
| 隐私 | 用户输入词仅用于查询与本地存储；若上传第三方，需在选项页说明 |
| 合规 | 遵守 Google/第三方服务条款；大规模采集建议走官方或授权接口 |

## 6. 技术方案要点（供开发评估，非最终实现）

> Google Trends **无稳定公开官方 API**，常见路径包括：**服务端封装**、**浏览器内受限频率的页面交互**、或 **第三方数据服务**。本 PRD 不绑定唯一实现，但要求 **验收标准 1～3** 在选定方案下可达成。

建议在 PRD 附录中补充「选型结论」：

- 数据获取方式（自建服务 / content script 注入 / 背景页 fetch）。
- 「上升趋势」字段与 **3.1** 的映射表。
- 速率限制与错误重试策略。

## 7. 数据结构与导出（建议）

**内存 / 存储结构（示例）**：

- `jobId`：任务 ID  
- `roots[]`、`reference[]`  
- `round`：当前轮次  
- `candidatesQueue`：当前待探测  
- `qualifiedSet`：全局合格词（可附原始上升值）  
- `edges`（可选）：`parentKeyword → childKeyword`，用于可视化或复盘  

**导出列（CSV 示例）**：

`keyword, riseValue, round, parentKeyword, collectedAt`

## 8. MVP 与后续版本

### 8.1 MVP（第一版）

- Tab + 表单 + 开始/停止 + 阈值与上限 + 轮次迭代 + 导出 + 本地历史（`chrome.storage`）。
- 单一数据源实现路径（先跑通一种）。

### 8.2 v2 候选

- 图表：趋势曲线对比（词根 vs 参考词）。
- 黑名单/白名单词缀过滤。
- 与外链/飞书等模块的联动（将词推送到表格）。

## 9. 风险与开放问题

1. **指标歧义**：「>100%」与产品展示是否一致，需与数据源字段统一文案。  
2. **封禁与稳定性**：高频请求可能导致 IP/账号限制，必须 throttle 与退避。  
3. **参考词在多轮中的角色**：若仅首轮使用，需在 UI 标明。  
4. **与「新词挖掘机」关系**：若为同一商业产品不同入口，需统一配额与账号体系（若适用）。

## 10. 验收清单（测试）

- [ ] 仅词根、无参考词时的行为符合产品设定（允许或禁止）。  
- [ ] 上升值恰为 100% 或恰为 1.0 时，边界是否符合「大于」定义。  
- [ ] 三轮迭代：第 2、3 轮队列来源正确，全局去重正确。  
- [ ] 达上限停止后，可下载完整已采集数据。  
- [ ] 停止后队列不再增长；历史状态为「已停止」。  
- [ ] 网络失败重试或单条失败后继续后续词。
