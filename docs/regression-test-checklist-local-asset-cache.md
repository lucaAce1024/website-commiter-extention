## 回归测试清单（本地图片缓存 / 站点保存 QUOTA 修复）

适用分支：`feat/local-asset-cache`

### 0. 准备工作

- **扩展已重新加载**：Chrome → 扩展程序 → 开发者模式 → 重新加载该扩展。
- **打开设置页**：扩展“详情” → 扩展程序选项（Options）。
- **准备两张图片**：一张 Logo、一张 Screenshot（建议各 ≥ 1MB，用于验证压缩、写入与读取）。

---

### 1. 站点管理（核心：不再触发 QUOTA / 保存失败）

- **新增站点（未启用本地图片缓存）**
  - 操作：站点管理 → 添加站点 → 只填写文本字段（siteName/siteUrl/email/description 等）→ 保存
  - 预期：
    - 保存成功，无 `QUOTA_BYTES quota exceeded`
    - 列表中站点出现
    - 提示文案包含“未启用本地图片缓存，Logo/截图不会保存”（若出现）

- **编辑站点（文本字段）**
  - 操作：编辑刚新增站点 → 修改标题/描述 → 保存
  - 预期：保存成功，改动生效

- **压力验证（多站点）**
  - 操作：连续新增 20+ 个站点（只填文本）并保存
  - 预期：均可保存，不再出现“保存失败：QUOTA_BYTES quota exceeded”

---

### 2. 本地图片缓存（设置/权限/迁移/清空）

在设置页 → **缓存管理** → **本地图片缓存（Logo / 截图）** 区块验证：

- **选择缓存文件夹**
  - 操作：点击“选择缓存文件夹” → 选择一个空目录（建议新建专用目录）
  - 预期：
    - 状态变为“已启用/权限 granted（或显示当前权限状态）”
    - 不报错

- **上传 Logo / Screenshot 并保存站点**
  - 操作：站点管理 → 编辑/新增站点 → 选择 Logo 文件 + Screenshot 文件 → 保存
  - 预期：
    - 保存成功
    - 站点列表 Logo 预览可显示（若权限允许读取）
    - 再次打开编辑弹窗时仍可看到预览（来自本地缓存读取）

- **迁移旧图片数据（如果历史数据里曾经存过 dataURL）**
  - 操作：点击“迁移旧图片数据”
  - 预期：
    - 成功提示：迁移完成，处理 N 张图片
    - 迁移后依旧能保存站点，不触发 QUOTA
    - 站点仍能预览/填充（若已授权目录且文件存在）

- **清空图片缓存**
  - 操作：点击“清空图片缓存”
  - 预期：
    - 本地缓存目录下扩展子目录被清理（best-effort）
    - 站点 `logoAsset/screenshotAsset` 引用被清空（UI 预览消失）
    - 其它站点文本字段不受影响

---

### 3. 表单自动填充（重点：file input 注入）

- **普通字段填充回归**
  - 操作：打开一个已支持的导航站提交页 → 打开 popup/侧栏 → 自动识别并填充
  - 预期：文本字段（URL/Name/Email/Description 等）填充行为不变

- **Logo/Screenshot 文件上传框自动填充**
  - 前置：站点已上传并落盘（第 2 节已验证），且导航站表单对应字段为 `<input type="file">`
  - 操作：执行自动填充
  - 预期：
    - `<input type="file">` 的文件被成功注入（页面侧可见“已选择文件”或对应站点 UI 反应）
    - 不出现卡死；失败时应在结果 errors 中显示“Failed to fill logo/screenshot file”

- **右键“填充单个字段”回归**
  - 操作：在 file input 上右键 → 选择填充 `logo`/`screenshot`
  - 预期：能把本地缓存图片注入 file input（异步完成，不阻塞其它功能）

---

### 4. 备份与恢复（不丢历史站点数据）

> 注意：本地图片缓存“文件本体”在磁盘上，备份 JSON 只会备份 `sites[]` 等结构化数据。

- **创建备份**
  - 操作：设置页 → 备份与恢复 → 创建备份（包含记录/缓存均勾选或按需）
  - 预期：下载 JSON 成功

- **合并恢复（推荐）**
  - 操作：选择刚导出的备份 → 恢复模式选“合并” → 恢复
  - 预期：
    - 站点列表数据仍完整
    - 不会因为本次改造导致站点“被清空”

- **完全替换恢复（高风险操作）**
  - 操作：恢复模式选“完全替换” → 恢复
  - 预期：
    - 恢复后站点/导航站等与备份一致
    - 这是“清空再写入”的设计行为，需确认备份文件是最新

---

### 5. 不相关功能冒烟（确保未被改动影响）

- **Ahrefs 缓存管理**：缓存管理页能正常加载 WHOIS/Ahrefs/批次列表；清理按钮可用
- **侧栏 Explore / 自动采集**：能正常打开，关键按钮可点击、状态展示正常（无需跑全流程，做冒烟即可）
- **LLM 设置**：设置页 LLM Provider/Model 下拉与保存不受影响
