### 步骤 2：任务批次 ID 与 URL 去重工具（FR-8, FR-11）

**目标**：实现批次 ID 生成（`batch_{YYYYMMDD}_{HHmmss}`，同秒可加序号）；实现 URL 标准化与去重、域名标准化与去重，供后续写入存储前调用。

**实现要点**：
- 新建 `lib/backlinkExplore.js`（或放在现有 lib 下）：`generateBatchId()`、`normalizeUrl(url)`、`normalizeDomain(domain)`、`dedupeUrls(urls)`、`dedupeDomains(domains)`。
- 标准化规则：URL 小写、去末尾斜杠、去 fragment、可选去默认端口；域名取 hostname 小写去重。

**验证操作**：
1. 在控制台或单元测试中调用 `generateBatchId()` 多次，确认格式为 `batch_YYYYMMDD_HHmmss`，同秒内第二次调用得到带序号的 ID（如 `_1`）。
2. `normalizeUrl('https://Example.com/path/#hash')` 得到 `https://example.com/path`（或约定格式）。
3. `dedupeUrls(['https://a.com/', 'https://A.com'])` 返回长度为 1 的数组；`dedupeDomains(['a.com', 'A.COM'])` 同理。

**步骤 2 如何自测（Side Panel 控制台）**：

1. **打开扩展 Side Panel**，切换到「外链采集」Tab。
2. **打开该面板的开发者工具**：在 Side Panel 窗口内右键 →「检查」/ Inspect，或从 Chrome 扩展管理页找到该扩展 →「Service Worker」旁若有「side panel」链接可点开；在 DevTools 里切到 **Console**。
3. 在控制台依次执行下面代码（函数由 `lib/backlinkExplore.js` 在面板中注入，可直接调用）：

   **① 批次 ID 格式与同秒序号**
   ```js
   // 连续调用两次，第二次在同秒内会带 _1
   await generateBatchId()
   await generateBatchId()
   ```
   - 预期：第一次类似 `batch_20260312_143052`，第二次若在同一秒内则类似 `batch_20260312_143052_1`；格式为 `batch_YYYYMMDD_HHmmss` 或带 `_N` 后缀。

   **② URL 标准化**
   ```js
   normalizeUrl('https://Example.com/path/#hash')
   ```
   - 预期：`'https://example.com/path'`（小写、去末尾斜杠、去 `#hash`）。

   **③ 域名标准化**
   ```js
   normalizeDomain('https://Blog.Example.COM/foo')
   normalizeDomain('example.com')
   ```
   - 预期：均为 `'blog.example.com'` 或 `'example.com'`（小写 hostname）。

   **④ URL 去重**
   ```js
   dedupeUrls(['https://a.com/', 'https://A.com', 'https://a.com/#x'])
   ```
   - 预期：长度为 1 的数组，如 `['https://a.com']`（同一站点不同写法算一条）。

   **⑤ 域名去重**
   ```js
   dedupeDomains(['a.com', 'A.COM', 'https://a.com/'])
   ```
   - 预期：长度为 1 的数组，如 `['a.com']`。

4. 若上述 ①～⑤ 结果与预期一致，则步骤 2 验证通过。

### 步骤 3：进度数据模型与持久化、暂停/继续/停止（FR-9, FR-10）

**目标**：定义批次进度结构（batchId, status, phase, urlList, urlProgress, lastProcessedIndex, discoveredSites, dugDomains, updatedAt）；实现保存/读取到 `chrome.storage.local`；暂停/停止时保存进度；继续时从 lastProcessedIndex 恢复。

**实现要点**：
- 在 `lib/backlinkExplore.js` 或单独 `lib/backlinkExploreStorage.js`：`saveBatch(batch)`、`loadBatch(batchId)`、`listBatches()`；写入前对 urlList、discoveredSites、dugDomains 调用去重（FR-11）。
- sidepanel 外链采集面板：暂停/继续/停止按钮点击时更新 status 并调用 save；继续时 load 当前批次后从 lastProcessedIndex 继续执行逻辑（与步骤 4/7 串联）。

**验证操作**：
1. 创建一批次（含 urlList、status: running），调用 saveBatch；关闭扩展或刷新后调用 loadBatch(batchId)，确认数据一致。
2. 模拟「暂停」：将 status 改为 paused 并 save；重新 load 后确认 status 为 paused，urlList/urlProgress 完整。
3. 模拟「停止」：将 status 改为 stopped 并 save；确认可 load 且可「从本批次继续」（将 status 改为 running 后继续）。
4. 确认写入前 urlList 已去重（重复 URL 仅一条）。

**步骤 3 如何自测**：

**一、控制台验证（storage 读写与结构）**

打开 Side Panel →「外链采集」Tab → 右键「检查」→ Console。依次执行：

**① 创建批次并保存，再读取，数据一致**
```js
const batchId = await generateBatchId();
const batch = createBatch(batchId, { type: 'test' });
batch.urlList = ['https://a.com', 'https://b.com'];
batch.urlProgress = { 'https://a.com': { done: true } };
batch.lastProcessedIndex = 1;
batch.status = 'running';
await saveBatch(batch);
const loaded = await loadBatch(batchId);
console.log('loaded.batchId', loaded?.batchId);
console.log('loaded.urlList', loaded?.urlList);
console.log('loaded.urlProgress', loaded?.urlProgress);
console.log('loaded.lastProcessedIndex', loaded?.lastProcessedIndex);
console.log('loaded.status', loaded?.status);
```
- 预期：`loaded` 与写入的 batch 一致（batchId、urlList、urlProgress、lastProcessedIndex、status 等）。

**② 暂停后重新 load，状态与数据完整**
```js
loaded.status = 'paused';
loaded.updatedAt = new Date().toISOString();
await saveBatch(loaded);
const afterPause = await loadBatch(batchId);
console.log('afterPause.status', afterPause?.status);
console.log('urlList 完整', afterPause?.urlList?.length === 2);
```
- 预期：`afterPause.status === 'paused'`，urlList 仍为 2 条。

**③ 停止后仍可 load，并可改为 running 继续**
```js
afterPause.status = 'stopped';
await saveBatch(afterPause);
const afterStop = await loadBatch(batchId);
console.log('afterStop.status', afterStop?.status);
afterStop.status = 'running';
await saveBatch(afterStop);
const continued = await loadBatch(batchId);
console.log('continued.status', continued?.status);
```
- 预期：afterStop.status 为 `'stopped'`，改为 running 并 save 后 load 得到 `'running'`。

**④ 写入前 urlList 去重**
```js
const batch2 = createBatch(await generateBatchId(), {});
batch2.urlList = ['https://x.com', 'https://X.com/', 'https://x.com#a'];
await saveBatch(batch2);
const loaded2 = await loadBatch(batch2.batchId);
console.log('去重后 urlList 长度', loaded2?.urlList?.length);
```
- 预期：去重后长度为 1（或 2，取决于实现是否在 save 前对 urlList 做 dedupe；若 saveBatch 内调用了 dedupeBatchBeforeSave，应为 1）。

**二、UI 验证（暂停/继续/停止与恢复）**

1. **创建批次**：在「外链采集」面板，Ahrefs 域名输入框随便填一个（如 `test.com`），点击「拉取反链」。预期：出现批次 ID（如 `batch_20260312_xxxxxx`），状态为 running，下方出现「暂停」「停止」按钮。
2. **暂停**：点击「暂停」。预期：提示「已暂停，进度已保存」；按钮变为「继续」可点。
3. **关闭并重开 Side Panel**：关闭 Side Panel，再重新打开，切到「外链采集」。预期：仍显示同一批次 ID，状态为 paused，「继续」可点。
4. **继续**：点击「继续」。预期：提示「已继续」，状态恢复为 running，「暂停」「停止」再次出现。
5. **停止**：点击「停止」。预期：提示「已停止，进度已保存」，「继续」可点；再次点击「继续」后该批次可再次变为 running。

完成上述「一」全部 4 项 +「二」全部 5 步即视为步骤 3 验证通过。

### 步骤 5：从外链页面评论区提取 URL（FR-2）

**目标**：用户输入外链文章 URL，扩展在目标页注入 content script，从评论区 DOM 中解析出评论者网站 URL，去重后返回并在面板展示、可加入待检测列表。

**实现要点**：
- content script（可新文件或扩展现有）：在指定 URL 的页面执行，定位 `.comments`、`#comments` 等评论区，收集 `a[href]`，过滤站内/广告/社交链接，标准化后去重。
- background 或 sidepanel：打开目标 Tab 或使用当前 Tab，注入并执行提取，通过 `chrome.tabs.sendMessage` 取回 URL 列表；结果写入当前批次 urlList 前做 dedupe（FR-11）。

**验证操作**：
1. 输入一篇含评论的博客文章 URL，点击「从评论区提取 URL」；确认扩展会新开 Tab 打开该 URL，加载完成后自动提取评论区链接，并在「待检测 URL 列表」中展示至少一条站外 URL。
2. 同一页面重复提取，确认结果去重无重复（新增条数 = 0 或仅新链接）。
3. 提取结果自动加入当前批次 urlList；若无当前批次则自动创建；排除域名配置会过滤掉本站等。

**步骤 5 实现说明**（已完成）：
- `content/formHandler.js`：新增 `extractCommentUrlsFromPage()`，先按 `#comments`、`.comments` 等选择器定位评论区；若无则按 `main`、`#content`、`.content`、`.forum-content`、`article` 等主内容区选择器；最后回退到 `document.body`。全页链接超过 2500 时仅处理前 2500 条以防卡顿。收集 `a[href]`，过滤站内/社交/短链；消息 `extractCommentUrls` 返回 `{ success, urls }`。控制台会输出 `[NavSubmitter] extractCommentUrls: { root, scanned, extracted }` 便于排查。
- sidepanel：点击「从评论区提取 URL」后校验输入、新开 Tab 打开目标 URL、等待 `tabs.onUpdated` 完成，`sendMessage` 触发提取；结果经 `filterUrlsExcludingDomains` + `dedupeUrls` 合并入当前批次 `urlList` 并保存；`renderExploreUrlList()` 刷新待检测列表；无批次时自动创建。

**步骤 5 如何自测（含论坛页）**：
1. 在 Side Panel「外链采集」中填入含评论或论坛帖子的 URL（如博客文章或论坛主题页），点击「从评论区提取 URL」。
2. 扩展会新开 Tab 并自动提取。在新打开的**页面**上右键 →「检查」，在 Console 中可看到 `[NavSubmitter] extractCommentUrls: { root: '...', scanned: N, extracted: M }`，用于确认使用的根节点与提取数量。
3. 回到 Side Panel 查看「待检测 URL 列表」是否出现站外链接；同一 URL 再次提取应显示「新增 0 条」或仅少量新链接（去重生效）。

### 步骤 6：Ahrefs 反链检查 — 直接 API 调用（FR-3）

**目标**：通过 CapSolver 解决 Cloudflare Turnstile 验证，再直接调用 Ahrefs 未公开 API 获取反链数据，无需打开 Ahrefs 页面。

**实现要点**：
- **方案（v2，当前）**：在 background.js 中实现三步 API 调用：
  1. 调用 CapSolver API 解决 Turnstile → 获取 token
  2. 用 token 调用 `https://ahrefs.com/v4/stGetFreeBacklinksOverview` → 获取 signedInput（含 signature + validUntil）
  3. 用 signedInput 调用 `https://ahrefs.com/v4/stGetFreeBacklinksList` → 获取反链列表
- 设置页（options.html）新增 CapSolver API Key 配置项
- sidepanel 通过 `chrome.runtime.sendMessage({ action: 'ahrefsDirectBacklinks', domain })` 调用 background 完成整个流程
- Ahrefs 的 Turnstile site_key 为 `0x4AAAAAAAAzi9ITzSN9xKMi`（固定值）
- CapSolver 约 3 秒出 token，整个流程约 5-10 秒

**前置条件**：
- 在 [capsolver.com](https://www.capsolver.com/products/cloudflare) 注册并获取 API Key
- 在扩展设置页「CapSolver 配置」中填入 API Key 并保存

**验证操作**：
1. 在设置页配置好 CapSolver API Key 并保存。
2. 输入域名（如 `ahrefs.com`），点击「拉取反链」；确认面板显示进度（解决验证中→获取签名→获取反链）。
3. 确认能拿到反链数据并在面板展示至少一条 urlFrom（待检测 URL 列表被填充）。
4. 反链列表展示 urlFrom；支持「加入待检测」且去重。

### 步骤 7：遍历 URL 检测可评论站点（FR-4）

**目标**：对当前批次 urlList 逐个打开 Tab，注入现有评论表单识别（formHandler/recognizeCommentForm），得到是否可评论、是否有 CAPTCHA、是否需登录；结果汇总并更新 urlProgress、discoveredSites；每步后持久化进度；支持暂停/停止后从 lastProcessedIndex 继续。

**实现要点**：
- 循环 urlList，从 lastProcessedIndex 开始；每个 URL 用 `chrome.tabs.create` 打开，等待 load 后 `sendMessage` 调用 recognizeCommentForm（或等价）；根据返回结果更新 urlProgress[url]、若可评论则加入 discoveredSites；lastProcessedIndex++；saveBatch；若用户点击暂停/停止则 break 并 save。
- 限流：同时仅 1 个 Tab 检测，检测完关闭 Tab 再下一个。

**验证操作**：
1. 待检测列表中有 2～3 个 URL（含已知可评论、已知不可评论），点击「遍历检测」；确认逐个打开、检测结果正确（可评论/不可评论）、进度条或计数更新。
2. 检测到一半点击「暂停」，确认进度已保存；点击「继续」从下一项继续。
3. 可评论的 URL 出现在「已发现可评论站」列表，且带 CAPTCHA/需登录标记（若实现）。

### 步骤 8：飞书表格写入（FR-5）

**实现要点**：
- 调用飞书多维表格 API（需文档确认 endpoint、鉴权）；从 storage 读取配置；写入时字段与 PRD 5.2 对应。
- 写入前可对本次写入列表做 URL 去重，避免同 URL 重复写入（可选，或由飞表唯一约束保证）。

**验证操作**：
1. 配置好飞书表格与 token，执行「写入飞书」；确认飞书表格中新增一条记录，且字段正确。
2. 多条可评论站写入后，确认每条对应一条飞书记录，无重复 URL（若实现去重或唯一约束）。

### 步骤 9：博客评论区抓取并提取站长域名（FR-6）

## 4. 步骤 6 v3 测试方法（纯 API 拉取反链）

### 前置条件

1. 在 [CapSolver](https://www.capsolver.com/) 注册账号并获取 API Key
2. 在扩展设置页 → 「CapSolver 配置」中填入 API Key 并保存

### 测试步骤

1. **重新加载扩展**：进入 `chrome://extensions/`，找到「外链提交助手」，点击刷新按钮重新加载
2. **打开 Side Panel**，切换到「外链采集」Tab
3. **在「Ahrefs 反链（纯 API）」区域**，输入一个域名（如 `aiheadcanongenerator.org`）
4. **点击「拉取反链」按钮**
5. **观察进度**：
   - 按钮下方应依次显示进度信息：
     - `步骤 1/3: 正在通过 CapSolver 解决 Turnstile 验证（约 3-10 秒）…`
     - `步骤 2/3: 正在获取签名（signedInput）…`
     - `步骤 3/3: 正在获取反链数据…`
     - `成功获取 N 条反链`（绿色）
   - 「待检测 URL 列表」应被反链 URL 填充
6. **打开扩展 Service Worker 控制台**（`chrome://extensions/` → 「外链提交助手」→ 点击「Service Worker」链接），查看日志：
   - `[Ahrefs API] CapSolver taskId: xxx`
   - `[Ahrefs API] CapSolver token 获取成功`
   - `[Ahrefs API] signature 获取成功, validUntil: xxx`
   - `[Ahrefs API] 获取到反链数量: N`

### 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `未配置 CapSolver API Key` | 未在设置页保存 Key | 设置 → CapSolver 配置 → 填入并保存 |
| `CapSolver createTask 失败` | Key 无效或余额不足 | 检查 CapSolver 后台余额和 Key |
| `stGetFreeBacklinksOverview 失败: HTTP 4xx` | Token 过期或域名格式有误 | 检查域名格式（不含 http://） |
| 反链数量为 0 | 该域名确实无反链或 Ahrefs 未收录 | 换一个已知有反链的域名测试 |
