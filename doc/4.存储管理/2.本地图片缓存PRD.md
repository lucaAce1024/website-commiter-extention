# 本地图片缓存 PRD（替代 chrome.storage，解决 QUOTA / 内存爆）

## 1. 文档信息

| 项目 | 说明 |
|------|------|
| 文档名称 | 本地图片缓存 PRD（Logo/截图落盘） |
| 版本 | 1.0 |
| 输出路径 | `doc/4.存储管理/2.本地图片缓存PRD.md` |
| 目标问题 | `QUOTA_BYTES quota exceeded`、站点保存失败、图片 dataURL 导致存储膨胀/内存峰值过高 |

---

## 2. 背景与问题

### 2.1 当前现状（基于代码审计）

- 站点管理（设置页）支持上传 **Logo / Screenshot**，并在保存站点时将图片以 **data URL（base64）** 形式写入 `chrome.storage.local` 的 `sites[]`。
- Content Script 在遇到 `<input type="file">` 的 Logo/截图字段时，会把 `logoDataUrl/screenshotDataUrl` 转为 `File` 并用 `DataTransfer` 注入上传框，实现自动填充上传控件。

### 2.2 主要问题

- **配额问题（必现）**：`chrome.storage.local` 单扩展配额有限（常见为 10MB 量级），base64 图片随站点数增加会快速触发 `QUOTA_BYTES quota exceeded`，表现为“保存站点失败/添加不上新站点”。
- **内存峰值问题（高风险）**：图片转 base64 的过程中会产生额外内存膨胀（base64 体积约增加 1/3），批量处理/迁移时更容易触发短时内存高峰。
- **IndexedDB 无法直接解决**：当前项目的 IndexedDB 用于 Ahrefs 缓存，并未替代 `sites[]` 中的图片存储；即使迁到 IDB，图片二进制仍可能导致存储膨胀与处理时内存峰值。

---

## 3. 目标（Goals）

- **G1**：Logo/截图等大二进制数据不再写入 `chrome.storage.*`（彻底消除 QUOTA 触发路径）。
- **G2**：保持现有“自动填充 file input”的能力（Logo/截图仍可自动注入 `<input type="file">`）。
- **G3**：尽可能小改动：不重构站点结构、不改核心业务流程，仅替换“大字段”的存储介质与读取方式。
- **G4**：提供明确的降级与迁移策略：未授权目录时不崩溃；允许用户迁移旧 dataURL 数据并清理。

---

## 4. 非目标（Non-goals）

- 不做跨设备同步（落盘缓存天然不跨设备）。
- 不引入 Native Messaging（本机常驻进程）作为 V1 必选方案。
- 不把全部业务数据迁移到本地文件；V1 只迁移“图片/大对象”。

---

## 5. 方案概述

### 5.1 总体设计

- **图片本体**：写入用户授权的 **本地缓存目录**（磁盘文件）。
- **索引/引用**：写入 `chrome.storage.local` 的 `sites[]`（仅存小字段：相对路径、mime、大小、时间戳等）。
- **读取与填充**：
  - 站点编辑 UI 预览需要图片时，从磁盘读取并生成临时 URL（仅在内存中，不落 storage）。
  - Content Script 填充 file input 时，通过消息机制从磁盘获取文件数据，构造 `File` 并注入上传框。

### 5.2 为什么必须“选择文件夹授权”而不是“直接填路径”

Chrome 扩展无法仅凭“路径字符串”静默读写用户磁盘；可行方案是让用户在扩展页面中 **选择一次目录** 并授予权限，扩展保存目录句柄（或等价授权信息），后续尽量复用授权。

## 6. 数据模型（最小改动）

### 6.1 本地图片引用结构

```ts
interface LocalAssetRef {
  kind: 'local-file';
  relPath: string;     // 相对缓存根目录的路径，例如: "sites/site_123/logo.jpg"
  mime: string;        // "image/jpeg"
  byteSize: number;    // 文件大小
  sha256?: string;     // 可选：去重/校验
  updatedAt: string;   // ISO 时间
}
```

### 6.2 Site 结构变化

- 新增：
  - `logoAsset?: LocalAssetRef | null`
  - `screenshotAsset?: LocalAssetRef | null`
- 旧字段：
  - `logoDataUrl` / `screenshotDataUrl`：V1 迁移后不再持久化写入（可保留兼容读取，但要提供迁移与清空）。

### 6.3 设置项

- `assetCacheEnabled: boolean`
- `assetCacheDirHandle: any`（目录句柄序列化结果；具体结构以实现选型为准）
- `assetCacheVersion: string`

## 7. 功能需求（FR）

### 7.1 缓存目录授权与状态展示

- **FR-1**：设置页提供“选择图片缓存文件夹”按钮，用户完成授权后，扩展记录授权信息并展示“已启用/可写”状态。
- **FR-2**：若权限失效或目录不可访问，UI 显示“需要重新授权”，并引导用户再次选择目录。

### 7.2 站点图片保存策略（替代 dataURL 持久化）

- **FR-3**：站点保存时，若用户上传了 Logo/截图文件：
  - 将图片压缩到约定上限（沿用现有 `< 1MB` 规则或可配置）
  - 写入缓存目录的固定结构路径（见 8.1）
  - 在 `sites[]` 中仅保存 `logoAsset/screenshotAsset` 引用
- **FR-4**：禁止在 `chrome.storage.local.sites[]` 中持久化存储 base64 dataURL（防止再次触发 QUOTA）。

### 7.3 表单自动填充（file input）

- **FR-5**：当页面表单字段为 `<input type="file">` 且标准字段为 `logo/screenshot`：
  - 优先使用 `logoAsset/screenshotAsset` 读取磁盘文件并注入
  - 若引用缺失或读文件失败，提示用户“需手动选择文件”（但不影响其它字段填充）

### 7.4 迁移与清理

- **FR-6（迁移）**：设置页提供“一键迁移旧图片数据”：
  - 扫描 `sites[]` 中的 `logoDataUrl/screenshotDataUrl`
  - 将其落盘并写回 `logoAsset/screenshotAsset`
  - 成功后清空对应 dataURL 字段（或删除字段）
- **FR-7（清理）**：设置页提供“清空磁盘图片缓存”：
  - 删除缓存目录中由扩展创建的文件（限定在扩展子目录内）
  - 清理 `sites[]` 中 `logoAsset/screenshotAsset` 引用

---

## 8. 存储结构与命名（建议）

### 8.1 目录结构

在用户选择的缓存根目录下创建扩展子目录（避免误删用户文件）：

- `{root}/backlink-collector-cache/`
  - `sites/{siteId}/logo.jpg`
  - `sites/{siteId}/screenshot.jpg`

> 若后续要做去重，可改为 `{root}/.../blobs/{sha256}.{ext}` 并在 Site 引用中记录 sha256。

---

## 9. 降级策略

- **未启用本地缓存 / 未授权目录**：
  - 站点编辑仍可保存（但不允许写入 dataURL）
  - Logo/截图字段降级为：仅支持 URL（`logo` / `screenshot`），文件上传自动填充提示“需要先设置缓存目录或手动上传”

---

## 10. 分阶段里程碑（最小改动路线）

### v0（止血版本：立即解除 QUOTA）

- 禁止把 `logoDataUrl/screenshotDataUrl` 写入 `chrome.storage.local.sites[]`
- UI 提示：Logo/截图上传功能暂时需要先配置缓存目录（否则只保存 URL，不保存上传文件）
- 验收：大量站点保存不再出现 `QUOTA_BYTES quota exceeded`

### v1（完整本地缓存：可用、可迁移）

- 增加“选择缓存目录”与状态展示
- 站点上传图片写磁盘，并写入 `logoAsset/screenshotAsset`
- Content Script 支持从磁盘读取并注入 file input
- 提供“一键迁移旧 dataURL”与“清空缓存”

### v2（体验与稳定性增强）

- 缓存大小统计、LRU/TTL 清理
- 内容 hash 去重（同图多站点复用）
- 更细粒度的错误提示与诊断（哪个站点/哪个文件失败）

---

## 11. 验收标准（AC）

- **AC-1**：在存在大量站点、每站点含 logo+截图的情况下，新增/编辑站点不再报 `QUOTA_BYTES quota exceeded`。
- **AC-2**：配置缓存目录后，导航站表单的 `<input type="file">` 能自动注入 Logo/截图文件（成功触发 `input/change`）。
- **AC-3**：扩展重载/浏览器重启后，仍能读到 `logoAsset/screenshotAsset` 并完成注入。
- **AC-4**：迁移功能可把已有 `logoDataUrl/screenshotDataUrl` 转为落盘引用，并在迁移后清除 dataURL，storage 体积显著下降。
