## 2. 背景与目标

### 2.1 背景

当前扩展支持在输入框上右键并选择「填充单个字段」。该能力可作为“自动填充不完整”时的人工补全手段，但 **补全后的元素定位（XPath/locator）不会被记录**，导致下次仍需重复人工操作，无法形成可复用的 SOP。

### 2.2 目标

1. **手动辅助可沉淀**：用户通过右键菜单完成某字段填充后，系统自动记录该元素的 XPath，并写回缓存，供下次自动填充优先复用。
2. **区分页面类型**：对同一 URL（hostname + pathname）明确标记该页面是：
  - **导航站提交页（nav）**：写入 `chrome.storage.local.fieldMappings`
  - **博客评论页（blog）**：写入 `chrome.storage.local.blogCommentFieldMappings`
3. **形成“覆盖率视角”**：缓存条目中可查询到本页每个标准字段对应的 XPath，以便你做 SOP 全量概览（后续可在 Options/侧栏做可视化）。

---

## 3. 用户流程（SOP）

### 3.1 导航站提交页（nav）

1. 用户执行“自动识别并填充”，若仍有字段未填或填错。
2. 用户在目标输入框上右键 → 选择「填充单个字段」→ 选择字段（如 siteName/email/siteUrl/...）。
3. 扩展完成填充后：
  - 记录该输入框 XPath
  - 将该字段映射写回 `fieldMappings[cacheKey]`（覆盖同字段旧映射）
4. 下次打开同页，再次自动填充时会优先命中缓存，达到稳定可用。

### 3.2 博客评论页（blog）

1. 用户执行“生成并填充评论”（或识别并填充），若姓名/邮箱/网址/评论框存在遗漏或定位错误。
2. 用户在目标输入框上右键 → 选择字段（commentName/commentEmail/commentWebsite/comment）。
3. 扩展完成填充后：
  - 记录该输入框 XPath
  - 将该字段映射写回 `blogCommentFieldMappings[cacheKey]`（覆盖同字段旧映射）
4. 下次再次执行自动评论填充时优先复用该映射。

## 4. 数据模型

### 4.1 Mapping 结构（复用现有）

```ts
interface FieldMappingEntry {
  standardField: string;
  locator: { type: 'xpath'; value: string };
  xpath: string;
  locatorDesc: string;
  source?: 'ai' | 'keyword' | 'cache' | 'manual';
  updatedAt?: string;
}
```

### 4.2 Nav 缓存结构（`fieldMappings`）

`chrome.storage.local.fieldMappings[cacheKey]`：

```ts
{
  mappings: FieldMappingEntry[],
  cachedAt: string,
  siteType?: 'nav',
  lastManualAssistAt?: string
}
```

### 4.3 Blog 缓存结构（`blogCommentFieldMappings`）

`chrome.storage.local.blogCommentFieldMappings[cacheKey]`：

```ts
{
  mappings: FieldMappingEntry[],
  submitButton?: { locator: object; xpath?: string; locatorDesc?: string } | null,
  consentCheckboxes?: Array<{ locator: object }> | null,
  cachedAt: string,
  siteType?: 'blog',
  lastManualAssistAt?: string
}
```

## 5. 功能需求（FR）

### 5.1 右键填充后写回缓存（核心）

- **FR-1**：当用户通过右键菜单填充单字段后，扩展必须记录目标元素的 XPath（`getXPath(el)`）。
- **FR-2**：记录的定位写入缓存时必须使用 `locator: { type: 'xpath', value: xpath }`，并保存 `xpath` 与 `locatorDesc`。
- **FR-3**：写回时合并策略为“同页同字段覆盖”：
  - 若该 `cacheKey` 下已有同 `standardField` 的映射，删除旧项，写入新项；
  - 保留其它字段映射不变。
- **FR-4**：写回时同时更新：
  - `cachedAt = now`
  - `lastManualAssistAt = now`
  - `siteType = nav/blog`

### 5.2 页面类型判定

- **FR-5**：对右键填充的写回缓存目标：
  - 若当前页处于 Blog 评论模式（commentFormState.hasForm 为 true，或已识别评论表单），写回 `blogCommentFieldMappings` 并标记 `siteType=blog`；
  - 否则写回 `fieldMappings` 并标记 `siteType=nav`。

### 5.3 Blog 的 comment 字段可选增强

- **FR-6（可选）**：当系统生成评论文本并填充时，应把 commentText 存入 `chrome.storage.session`（按当前页 cacheKey），以便用户后续用右键菜单填充 `comment` 字段时可直接复用。

---

## 6. 非功能需求（NF）

- **NF-1**：不得影响现有自动识别与填充主路径（AI/keyword/cache）。
- **NF-2**：写回的数据必须尽量小（仅 xpath/字段名等），避免触发存储配额问题。
- **NF-3**：失败降级：若 XPath 生成失败或写回失败，不阻塞本次填充（仅记录 warning）。

---

## 7. 验收标准（AC）

- **AC-1**：在某页用右键填充一个字段后，刷新页面再执行自动填充，该字段能稳定命中同一输入框。
- **AC-2**：对同一字段重复右键填充会覆盖旧 XPath 映射。
- **AC-3**：nav 页面写入 `fieldMappings` 且 `siteType=nav`；blog 页面写入 `blogCommentFieldMappings` 且 `siteType=blog`。
