### Task 5：Agent Loop 核心框架（Day 3）

**改动文件**：`lib/fullAiAgent.js`

**开发内容**：

1. 新增 `AGENT_SYSTEM_PROMPT` 常量（见 README.md 7.3 节）
2. 实现 `buildRoundMessage(roundIndex, snapshot, prevResult, fillData)` — 构建每轮 user message
3. 实现 `callAgentLLM(messages, llmConfig, fetchLlmWithRetry)` — 调用 LLM 并解析 JSON 响应
4. 实现 `trimConversationHistory(messages, opts)` — 控制历史长度，旧轮替换为摘要
5. 实现 `runAgentLoop(tabId, fillData, llmConfig, fetchLlmWithRetry, log)` — Agent Loop 主循环
6. 改造 `runFullAiTask()` — 先走快速路径（现有启发式），失败后调用 `runAgentLoop`

**核心逻辑**（`runAgentLoop`）：
```
for round in [0, MAX_ROUNDS):
  1. Observe: takeSnapshot
  2. round==0: 尝试程序弹窗关闭 + 启发式，成功则 return
  3. Decide: buildRoundMessage → push to messages → callAgentLLM → push response
  4. 判断 status: no_form/blocked → return failure
  5. Act: fullAiExecute(actions)
  6. Evaluate: status==done && allOk → return success
  7. continue → sleep(800) → next round
```

**依赖**：Task 1-4（弹窗 + 关键词 + label + 回退 已就绪）

## 四、Phase 3：优化与稳定性

### Task 9：同域名弹窗缓存（Day 7+）

批量模式下，如果同域名前一个 URL 未检测到弹窗，后续同域名 URL 跳过弹窗检测，节省 1-2s/页。

### Task 10：成功模式缓存

Agent Loop 成功后，将域名 + 字段映射（uid → slot）保存，下次同域名直接复用，不进入 Agent Loop。

### Task 11：失败 Snapshot 日志

每次 Agent Loop 失败时，将最后一轮 Snapshot + 失败原因保存到 `chrome.storage.local`，便于后续分析和补充规则。

## 七、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| LLM 返回格式不稳定（非 JSON） | 中 | Agent Loop 单轮浪费 | JSON 解析失败时跳过本轮，下一轮重新给 Snapshot |
| 弹窗误点击关掉正常按钮 | 低 | 页面状态异常 | 仅检测 fixed/sticky + z-index > 100 |
| 多语言关键词冲突 | 低 | 字段映射错误 | 关键词精确包含匹配，AI 兜底修正 |
| Snapshot 文本太长导致 token 超限 | 中 | API 报错 | 截断策略 + maxLen 控制 |
| Agent Loop 5 轮仍失败 | 中 | 任务失败 | 记录失败 Snapshot，人工分析补充规则 |
| 批量模式下 LLM 调用成本增加 | 中 | 费用上升 | 快速路径优先，大部分简单表单 0 次 LLM |
