### Task 5：Agent Loop 核心框架（Day 3）

**改动文件**：`lib/fullAiAgent.js`

**开发内容**：

1. 新增 `AGENT_SYSTEM_PROMPT` 常量（见 README.md 7.3 节）
2. 实现 `buildRoundMessage(roundIndex, snapshot, prevResult, fillData)` — 构建每轮 user message
3. 实现 `callAgentLLM(messages, llmConfig, fetchLlmWithRetry)` — 调用 LLM 并解析 JSON 响应
4. 实现 `trimConversationHistory(messages, opts)` — 控制历史长度，旧轮替换为摘要
5. 实现 `runAgentLoop(tabId, fillData, llmConfig, fetchLlmWithRetry, log)` — Agent Loop 主循环
6. 改造 `runFullAiTask()` — 先走快速路径（现有启发式），失败后调用 `runAgentLoop`

**核心逻辑**（`runAgentLoop`）：
```
for round in [0, MAX_ROUNDS):
  1. Observe: takeSnapshot
  2. round==0: 尝试程序弹窗关闭 + 启发式，成功则 return
  3. Decide: buildRoundMessage → push to messages → callAgentLLM → push response
  4. 判断 status: no_form/blocked → return failure
  5. Act: fullAiExecute(actions)
  6. Evaluate: status==done && allOk → return success
  7. continue → sleep(800) → next round
```

**依赖**：Task 1-4（弹窗 + 关键词 + label + 回退 已就绪）

## 四、Phase 3：优化与稳定性

### Task 9：同域名弹窗缓存（Day 7+）

批量模式下，如果同域名前一个 URL 未检测到弹窗，后续同域名 URL 跳过弹窗检测，节省 1-2s/页。

### Task 10：成功模式缓存

Agent Loop 成功后，将域名 + 字段映射（uid → slot）保存，下次同域名直接复用，不进入 Agent Loop。

### Task 11：失败 Snapshot 日志

每次 Agent Loop 失败时，将最后一轮 Snapshot + 失败原因保存到 `chrome.storage.local`，便于后续分析和补充规则。

### Task 13：提交后登录重定向处理

#### 13a：飞书 Sheets API 同步（已内嵌在 `options/options.js` 中）

**已实现**的 API 调用链路：

1. `tenant_access_token` — 复用飞书配置的 App ID / App Secret
   ```
   POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal/
   Body: { "app_id": appId, "app_secret": appSecret }
   ```

2. 查询工作表列表 — 按名称找到目标 sheetId
   ```
   GET /sheets/v3/spreadsheets/{spreadsheetToken}/sheets/query
   → 按 title === sheetName 匹配
   ```

3. 读取全部数据
   ```
   GET /sheets/v2/spreadsheets/{spreadsheetToken}/values/{sheetId}!A1:Z{rowCount}
   → values[][]（二维数组：首行表头，后续行为数据）
   ```

4. 解析表头列名→字段映射，逐行转为 `SiteCredential[]`，写入 `chrome.storage.local`

**配置项**：复用飞书配置 App ID / App Secret + 额外两项：

| 项目                | 值                                        | 存储 key                          |
| ----------------- | ---------------------------------------- | ------------------------------- |
| 电子表格 Token        | 默认预填 `FgWhsDQdNhWfVot4787ceNMXnDd`       | `credConfig.spreadsheetToken`   |
| 工作表名称             | 默认预填「媒体账号统计」                              | `credConfig.sheetName`          |

**飞书应用权限要求**：
- `sheets:spreadsheet:readonly` — 读取电子表格数据

**数据源**：

| 项目        | 值                                                                               |
| --------- | ------------------------------------------------------------------------------- |
| 飞书电子表格    | https://my.feishu.cn/sheets/FgWhsDQdNhWfVot4787ceNMXnDd                        |
| 工作表名称     | 媒体账号统计                                                                          |
| 表格列       | 平台 \| 账号名 \| 登录密码 \| 登录邮箱 \| 网址                                                |
| 数据示例      | `gamedev \| luna123 \| %Dxf18710360436 \| l21210896@gmail.com \| https://gamedev.net/` |

#### 13d：登录重定向主流程

**改动文件**：`background.js`（或 `lib/fullAiAgent.js`）

1. 提交动作后检测 URL 是否发生变化（与初始 URL 比对）
2. 若跳转 → 二次 `takeSnapshot`，识别登录表单（Email/Password/Log in）
3. 调用 `findCredentialByDomain(currentUrl)` 查找凭据
4. **有凭据**：按登录表单字段类型填充
   - Email/Username 字段 → 优先填 `email`，若无邮箱字段则填 `username`
   - Password 字段 → 填 `password`
   - 点击 Login/Submit 按钮
   - 等待登录完成 → 检测是否回到评论页 → 重新提交评论
5. **无凭据**：返回错误信息 `{ status: 'need_login', message: '该站点 (domain) 无登录凭据，请补充到飞书表格或手动注册' }`

**同步时机**：

- **Options 页手动同步**：点击「从飞书同步」→ 立即拉取
- **批量任务启动前自动同步**：每次批量提交前自动拉取最新数据
- **token 缓存**：`tenant_access_token` 缓存在 `chrome.storage.session`，有效期 2h 内复用

**验收标准**：PRD FR-7 AC-1～AC-4

3. 批量模式中 `success: true` 仅在验证通过时设置；验证失败或超时一律标记为失败

**验收标准**：PRD FR-9 AC-1、AC-2

## 七、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| LLM 返回格式不稳定（非 JSON） | 中 | Agent Loop 单轮浪费 | JSON 解析失败时跳过本轮，下一轮重新给 Snapshot |
| 弹窗误点击关掉正常按钮 | 低 | 页面状态异常 | 仅检测 fixed/sticky + z-index > 100 |
| 多语言关键词冲突 | 低 | 字段映射错误 | 关键词精确包含匹配，AI 兜底修正 |
| Snapshot 文本太长导致 token 超限 | 中 | API 报错 | 截断策略 + maxLen 控制 |
| Agent Loop 5 轮仍失败 | 中 | 任务失败 | 记录失败 Snapshot，人工分析补充规则 |
| 批量模式下 LLM 调用成本增加 | 中 | 费用上升 | 快速路径优先，大部分简单表单 0 次 LLM |
