# PRD — AI 增强评论提交系统 v2

> 产品需求文档 | 版本 2.0 | 2026-03-09

---

## 1. 背景与目标

### 1.1 当前痛点


| #   | 问题                               | 影响                  | 严重度  |
| --- | -------------------------------- | ------------------- | ---- |
| P1  | Cookie/隐私弹窗遮挡表单，标准流程和批量模式无法处理    | 大量页面直接返回"找不到form表单" | 🔴 高 |
| P2  | 启发式关键词仅覆盖英文+中文，多语言页面匹配全部失败       | 日/德/法/斯/捷等语言页面无法提交  | 🔴 高 |
| P3  | 表单检测强依赖 `<form>` 标签，非标准布局直接判定无表单 | Disqus、自定义组件等场景失败   | 🟡 中 |
| P4  | 流程每一步单轮无状态，失败后无法自修复              | 任何意外都导致整个任务失败       | 🔴 高 |
| P5  | 勾选确认项（checkbox）识别范围有限            | 未勾选必要项导致提交被拒        | 🟡 中 |
| P6  | 已关闭评论的页面仍然尝试识别和调用 LLM            | 批量模式浪费时间和 token     | 🟡 中 |


### 1.2 目标

**一句话**：通过弹窗预处理 + 多语言增强 + 多轮对话 Agent Loop，将评论提交成功率从当前约 40% 提升到 75%+。

**量化指标**：


| 指标                   | 当前         | 目标  |
| -------------------- | ---------- | --- |
| 标准英文 WordPress 表单成功率 | ~70%       | 95% |
| 多语言表单成功率             | ~10%       | 70% |
| 有弹窗页面成功率             | ~0%        | 80% |
| 非标准表单成功率             | ~5%        | 50% |
| 批量模式平均单页耗时           | 15s（含大量失败） | 12s |
| 无评论页面判定耗时            | 30s+（超时）   | <8s |

## 2. 用户场景

### 场景 1：单页评论提交（Side Panel）

用户在 Side Panel 中选择目标站点，点击"生成评论并填充"。系统自动：

1. 关闭页面上的弹窗（如有）
2. 检测评论表单
3. 生成评论内容
4. 填充所有字段（Name/Email/Website/Comment）
5. 勾选必要的 checkbox
6. 点击提交

**增强后变化**：

- 步骤 1 新增弹窗预处理（之前不存在）
- 步骤 2-5 遇到异常时自动进入 Agent Loop 自修复（之前直接失败）

### 场景 2：批量评论提交

用户从飞书同步 URL 列表，点击"开始批量提交"。系统逐个打开 URL 并自动完成评论流程。

**增强后变化**：

- 每个 URL 先走弹窗预处理 + 快速路径
- 快速路径失败时自动进入 Agent Loop
- 无评论表单的页面快速跳过（<8s）
- 不可绕过的障碍（reCAPTCHA）快速终止并标记

### 场景 3：完全 AI 识别模式

用户勾选"完全AI识别"后提交。当前流程保留，但改造为两级架构：

- 快速路径（程序启发式）→ 成功则 0 次 LLM 调用
- Agent Loop（多轮对话自修复）→ 作为 fallback

## 3. 功能需求

### FR-1：弹窗预处理


| 项目       | 说明                                                                           |
| -------- | ---------------------------------------------------------------------------- |
| **描述**   | 在任何评论填充流程开始前，自动检测并关闭页面上的 Cookie/隐私/GDPR 同意弹窗                                 |
| **触发条件** | 页面加载完成后，评论流程启动时自动执行                                                          |
| **处理方式** | 第一级：纯程序选择器 + fixed 元素文本匹配（<500ms） 第二级：Snapshot + LLM 识别按钮（仅第一级无效时触发）         |
| **最大轮次** | 程序级 2 轮 + LLM 级 1 轮                                                          |
| **适用范围** | 标准流程 + 完全AI识别 + 批量模式                                                         |
| **验收标准** | AC-1: 能关闭 CookieConsent、OneTrust、GDPR 类弹窗 AC-2: 不误点击正常页面元素 AC-3: 弹窗处理耗时 < 3s |


### FR-2：表单检测增强


| 项目       | 说明                                                      |
| -------- | ------------------------------------------------------- |
| **描述**   | 当标准 `<form>` 检测失败时，通过 Snapshot 辅助检测评论区是否存在              |
| **新增能力** | 1) Snapshot 搜索 textbox/textarea 节点 2) 快速判定"不可评论"页面并提前终止 |
| **验收标准** | AC-1: 评论区不在 `<form>` 内的页面能被识别 AC-2: 已关闭评论的页面在 8s 内终止    |


### FR-3：多语言元素识别


| 项目       | 说明                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------- |
| **描述**   | 扩展启发式匹配的关键词覆盖范围，支持 10+ 种语言                                                                               |
| **覆盖语言** | 英/中/日/德/法/西/葡/意/斯洛文尼亚/捷克/韩/俄                                                                             |
| **增强内容** | 1) 多语言 SLOT_KEYWORDS 2) `<label for>` 关联采集 3) textarea 回退（唯一 textarea = comment） 4) `type="submit"` 直接匹配 |
| **验收标准** | AC-1: 日语/德语/斯洛文尼亚语评论表单 Name/Email/Website/Comment 全部正确匹配 AC-2: 不依赖 LLM 即可完成常见多语言表单                       |


### FR-4：勾选确认项增强


| 项目       | 说明                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------- |
| **描述**   | 识别并自动勾选提交前必要的 checkbox                                                                            |
| **增强内容** | 1) 扩展 checkbox 关键词 2) 识别 role=switch、aria-checked 等非标准 checkbox 3) "Save my name" 类 checkbox 默认勾选 |
| **验收标准** | AC-1: WordPress "Save my name" checkbox 能自动勾选 AC-2: "Notify me" / "I agree to terms" 能自动勾选        |


### FR-5：多轮对话 Agent Loop


| 项目          | 说明                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **描述**      | 当程序启发式路径失败时，启动带上下文的多轮 AI Agent Loop 进行自修复                                                                                         |
| **核心机制**    | Observe(Snapshot) → Decide(LLM) → Act(Execute) → Evaluate(Result) 循环                                                              |
| **触发条件**    | 快速路径（程序启发式）执行失败后自动触发                                                                                                              |
| **最大轮次**    | 5 轮                                                                                                                               |
| **上下文管理**   | messages 数组累积历史，保留最近 4 轮完整内容，旧轮自动截断为摘要                                                                                            |
| **AI 输出格式** | `{ thought, actions: [{op, uid, value?, checked?}], status }`                                                                     |
| **终止状态**    | `done`（成功提交）/ `no_form`（无表单）/ `blocked`（不可绕过）                                                                                     |
| **验收标准**    | AC-1: 弹窗→表单→提交的完整流程能在 3 轮内完成 AC-2: element_not_found 后能在下一轮自动修正 AC-3: reCAPTCHA 页面 1 轮终止 AC-4: 总 token 消耗 ≤ 10000/任务 AC-5: 批量模式可用 |


### FR-6：快速路径保留


| 项目       | 说明                                                        |
| -------- | --------------------------------------------------------- |
| **描述**   | 简单表单仍走程序启发式快速路径，不消耗 LLM token                             |
| **流程**   | 弹窗预处理（程序）→ Snapshot → 启发式匹配 → 执行                          |
| **验收标准** | AC-1: 标准 WordPress 评论表单走快速路径，0 次 LLM 调用 AC-2: 快速路径耗时 < 5s |

## 4. 非功能需求

### NFR-1：性能


| 场景               | 目标耗时  | LLM 调用       |
| ---------------- | ----- | ------------ |
| 简单表单（快速路径）       | < 5s  | 0（仅评论生成 1 次） |
| 有弹窗 + 标准表单       | < 10s | 0-1          |
| 复杂表单（Agent Loop） | < 30s | 2-4 轮        |
| 无评论表单页面          | < 8s  | 0-1          |
| 遇到 reCAPTCHA     | < 10s | 0-1          |


### NFR-2：成本

- 单次任务 token 预算：≤ 10000 tokens（Agent Loop 路径）
- 快速路径 token 消耗：0（仅评论生成消耗 ~500 tokens，不在本次统计范围）
- 批量 100 个 URL 总 token：约 200k-500k tokens（取决于失败率）

### NFR-3：兼容性

- 所有增强不改变现有消息协议（`chrome.runtime.onMessage` 接口不变）
- 现有缓存/关键词/AI OneShot 路径正常工作，不受影响
- Side Panel UI 无需改动（操作由 background → content 驱动）

### NFR-4：可观测性

- Agent Loop 每轮的 `thought`、`actions`、执行结果输出到控制台日志
- 批量模式每个 URL 的结果（成功/失败原因/轮次数/耗时）记录到任务结果

## 6. 不做什么（Out of Scope）


| 项目                                  | 原因                     |
| ----------------------------------- | ---------------------- |
| reCAPTCHA / hCaptcha 自动绕过           | 技术不可行 + 违反 TOS         |
| 需要登录才能评论的页面                         | 涉及账号管理，超出当前范围          |
| Disqus iframe 内部操作                  | 跨域限制，需要单独方案            |
| UI 界面改动                             | 本次仅改后端逻辑，不动 Side Panel |
| 导航站提交模式（formHandler 标准流程的 fillForm） | 本次聚焦评论提交，导航站后续迭代       |
