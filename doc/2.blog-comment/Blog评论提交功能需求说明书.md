# Blog 评论提交功能需求说明书

## 一、产品背景与目标

在博客/文章页面留下评论是常见的外链与互动方式。目标是在当前插件中新增 **Blog 评论模式**：用户打开一篇博客的评论提交区后，可一键生成评论内容并填充 Comment、Name、Email、个人网站 URL，并自动点击提交按钮；若页面出现防 spam 验证（如算术验证），则暂停并交由用户手动完成。

与现有「导航站提交」并列，作为 Popup 中的第二种工作模式，复用现有站点档案、LLM 配置与 AI 识别能力。

---

## 二、Blog 评论页面共性

### 2.1 页面结构

- **从上到下**：博客正文区 → 评论展示区 → **评论提交区**。
- 本功能仅针对 **评论提交区** 的表单进行识别、填充与提交。

### 2.2 评论提交区常见字段

| 字段 | 说明 | 必填性 | 数据来源 |
|------|------|--------|----------|
| Comment | 评论文本（多行） | 通常必填 | 由 AI 根据当前页 Metadata 生成，约 200 字符 |
| Name | 评论者姓名 | 必填 | 当前选中的「站点档案」中的站点名称或单独配置的评论用昵称 |
| Email | 邮箱（通知与防垃圾） | 通常必填 | 当前站点档案的「联系邮箱」 |
| 个人网站 URL (Website) | 个人/站点链接 | 选填 | 当前站点档案的「网站 URL」 |

### 2.3 多语言与样式差异

- 站点可能是 **多语言**（如英文 "Leave a Reply"、捷克语 "Nový komentář"、"Jméno"、"Komentář" 等）。
- 字段依赖 **AI 做语义识别与定位**，与导航站表单的 AI 识别方式一致，但标准字段集合不同（见下）。

### 2.4 防 Spam 验证（重要约束）

- 部分站点在评论表单中带有 **防 spam 验证**，例如：
  - 算术题："Sum of 1 + 10 ?"、"Součet čísel šest a dvě"（6+2）
  - 图形验证码、reCAPTCHA 等
- **需求**：在填充前或填充后若检测到此类验证字段，**暂停自动流程**，提示用户手动完成验证后再自行提交，不自动点击提交按钮。

## 三、功能需求详述

### 3.1 Popup 新增 Tab：Blog 评论模式

1. **Tab 切换**
   - 在 Popup 顶部或显眼位置增加 **模式切换**（如 Tab 或分段控件）：
     - **导航站**：当前已有逻辑（当前站点、当前页面、自动识别并填充、AI 智能识别等）。
     - **Blog 评论**：仅展示与 Blog 评论相关的 UI 与操作。
   - 默认可保持「导航站」为默认 Tab；或根据当前 URL 是否像博客页做简单建议（可选）。

2. **Blog 评论 Tab 内容**
   - **当前站点**：继续使用现有站点下拉框（Name、Email、Website 从该站点档案读取）。
   - **当前页面状态**：
     - 显示当前页域名；
     - 显示「评论表单识别状态」（未检测 / 已识别，可填字段数）；
     - 若检测到防 spam 验证，显示「检测到验证项，将暂停自动提交」等提示。
   - **主操作按钮**：
     - **「生成评论并填充」**（或「一键填充评论」）：  
       先根据当前页面的 **Metadata（如 `<title>`、`<meta name="description">`）** 调用现有 LLM 能力生成约 200 字的评论内容，再识别评论表单字段（Comment / Name / Email / Website），填充后若**未**检测到防 spam 验证则自动点击提交按钮；提交后进入 **验证环节**：重新读取页面，在页面中查找可点击的、指向本站的链接，找到则视为成功。
     - 若检测到防 spam 验证则仅填充并提示用户手动完成验证与提交；用户自行提交后，可提供 **「验证本次提交」** 按钮，再次执行「重新读取页面 + 查找可点本站链接」以确认成功。
   - **快捷操作**：
     - 「打开 Blog 评论站点列表」：跳转到 Options 中维护的「Blog 评论站点列表」或单独弹窗/页；
     - 「设置」：与现有设置入口一致即可。

3. **Comment 内容生成**
   - **输入**：当前页面的 `document.title` 与 `document.querySelector('meta[name="description"]')?.content`（或等价 Metadata），由 Content Script 采集后传给 Background。
   - **生成**：在 Background 中调用现有 **LLM 服务**（与导航站介绍语生成、表单识别共用配置），请求「根据页面标题与描述，生成一条约 200 字符的、自然、友好的英文评论」；若站点语言可识别，可扩展为「按页面语言生成评论」（后续迭代）。
   - **输出**：纯文本，约 200 字符，供填入 Comment 字段。

### 3.2 评论表单识别与填充

1. **标准字段定义（Blog 评论专用）**
   - 与导航站标准字段区分，在插件内使用一套 **评论专用标准字段**，例如：
     - `comment`：评论文本
     - `commentName`：评论者姓名（必填）
     - `commentEmail`：评论者邮箱（通常必填）
     - `commentWebsite`：个人网站 URL（选填）

2. **识别方式**
   - **优先 AI 识别**：将评论提交区内的表单结构（或整页中与「评论/回复」相关的 form）提取为表单元数据，发送给 LLM，要求映射到上述 4 个标准字段 + 识别「提交按钮」；多语言标签依赖 AI 理解（如 Jméno→commentName, Komentář→comment）。
   - **规则兜底**：可维护 comment/name/email/website 的多语言关键词与常见 `name`/`id`/`placeholder`/`aria-label` 规则，在未配置 LLM 或 AI 失败时使用，准确率可能略低。
   - **缓存**：按「域名 + 路径」或「域名 + 页面特征」缓存「评论表单字段映射 + 提交按钮定位」，同一博客再次访问时直接复用。

3. **填充数据来源**
   - **Comment**：本节 3.1 中生成的评论文案。
   - **Name**：当前选中站点档案的 `siteName`（或后续扩展的「评论用昵称」）。
   - **Email**：当前选中站点档案的 `email`。
   - **Website**：当前选中站点档案的 `siteUrl`。

4. **防 Spam 验证检测（在填充前执行）**
   - 在 **执行填充之前**，对当前评论表单所在 DOM 进行检测：
     - 沿用现有验证码选择器（iframe[src*="recaptcha"]、div[class*="captcha"] 等）；
     - **新增**：算术/文字类验证（如 "sum of", "součet", "1 + 10", "答"、"验证" 等）及其对应输入框。
   - 若检测到任一验证项：
     - **仍可填充** Comment / Name / Email / Website；
     - **不自动点击提交按钮**；
     - 在 Popup 或页内提示：「已填充评论表单；检测到验证项，请手动完成验证后点击提交。」
   - 若未检测到验证项：填充完成后自动定位并点击「提交 comment 的按钮」。

5. **提交按钮识别**
   - 由 AI 识别或规则识别「提交评论」按钮（如 "Post Comment"、"Submit"、"Komentovat"、"发表评论" 等），返回其定位信息（id/name/selector/XPath 等），填充完成后执行一次 click。

6. **提交后验证环节**
   - **目的**：确认评论已成功展示在页面上（即本站链接已出现在评论区），避免误判为「已提交」。
   - **流程**：
     1. 在自动点击提交按钮之后（或用户手动完成验证并提交之后），**重新读取当前页面**（等待页面刷新/跳转或评论区 DOM 更新完成，必要时短时轮询或监听 DOM 变化）。
     2. 在页面中查找 **指向当前站点档案「网站 URL」的链接**：
        - 即 `a[href]` 的 `href` 与用户站点 URL 一致或同源（可做规范化：去掉末尾斜杠、协议统一为 https 等再比较）。
     3. 该链接必须 **可点击**（未被 `disabled`、未被 `display:none` 或 `visibility:hidden` 等遮挡、在视口或可滚动区域内）。
   - **判定**：
     - **找到可点的本站链接** → 验证成功，视为本次评论提交成功；可提示「验证成功：已在页面中找到您的站点链接」并记录为成功。
     - **未找到或链接不可点** → 验证未通过；可提示「未在页面中检测到您的站点链接，请确认评论是否已发布」并记录为待确认或失败，不视为成功。
   - **实现注意**：评论提交后目标页可能整页刷新或仅评论区局部更新，需在合适的时机（如提交后等待 2–5 秒再执行）执行「重新读取页面 + 查找本站链接」；查找范围可限定在评论展示区容器内，减少误匹配。

### 3.3 批量提交：按站点列表循环

1. **Blog 评论站点列表**
   - 在插件中维护一个 **「Blog 评论站点列表」**（与「导航站列表」并列）：
     - 每条记录：站点名称（便于区分）、**目标 URL**（具体某篇博客的评论页 URL）。
   - 支持：新增、编辑、删除、导入/导出（如 JSON），与导航站列表的交互方式类似；可放在 Options 的单独 Tab 或同一 Tab 下分块。

2. **批量提交流程**
   - 用户在 Popup 的 Blog 评论 Tab 中选择「批量提交」或「按列表依次提交」：
     - 按列表顺序逐个打开 URL（新 Tab 或当前 Tab 跳转）；
     - 对每个 URL：注入/激活 Content Script → 生成评论 → 识别评论表单 → 检测验证项；
       - 若有验证项：仅填充，不点击提交，并记录「需人工验证」；
       - 若无：填充并点击提交，然后执行 **验证环节**（重新读取页面，查找可点的本站链接）；找到则记录「已提交并验证成功」，未找到则记录「已提交待验证」或「验证未通过」。
   - 每个站点执行后可根据策略：等待数秒再切下一站（避免请求过快）；或由用户手动「下一个」。
   - 提供简单进度与结果汇总（验证成功数、需人工数、验证未通过/失败数）。

3. **与「单页一键填充」的关系**
   - 单页逻辑是批量的一步；批量 = 多次「打开 URL → 执行单页生成+识别+填充+（无验证时）提交」。

## 四、数据与存储

### 4.1 存储结构

- **blogCommentSites**：数组，元素形如：
  - `id`、`name`（展示名）、`url`（博客评论页 URL）、`createdAt`、`updatedAt`。
- **blogCommentFieldMappings**：按域名（或 domain+path）缓存的「评论表单字段映射 + 提交按钮」结果，结构可与现有 `fieldMappings` 类似，key 区分 `nav_${domain}` 与 `blog_${domain}` 或单独命名空间。
- **评论提交记录（可选）**：如 `blogCommentRecords`，记录某 URL、某站点档案、提交时间、状态（已提交/需人工验证/失败），便于统计与去重。

### 4.2 与现有数据复用

- **站点档案（sites）**：继续用现有站点档案提供 Name、Email、Website；当前选中的站点即「评论身份」。
- **LLM 配置（settings.llmConfig）**：评论生成与评论表单 AI 识别共用，不新增配置项。
- **导航站列表与字段映射**：与 Blog 评论列表、评论字段映射分离存储，互不影响。

## 五、UI/UX 要点

1. **Popup**
   - 模式切换（导航站 | Blog 评论）清晰；
   - Blog 评论 Tab 下无导航站专用项（如「按字段填充」可隐藏或改为评论字段维度的可选展示）。
2. **Options**
   - 新增「Blog 评论站点列表」管理（增删改、导入导出），与导航站列表入口分开。
3. **提示与反馈**
   - 生成评论中、识别中、填充中：按钮或状态文案明确；
   - 检测到验证时：明确说明「已填充，请手动完成验证并提交」；
   - **验证环节**：提交后显示「验证中…」；找到可点本站链接时提示「验证成功：已在页面中找到您的站点链接」；未找到时提示「未检测到您的站点链接，请确认评论是否已发布」；
   - 批量结束时：简要汇总验证成功/需人工/验证未通过数量。

## 六、非功能需求

1. **权限**：不新增敏感权限；使用现有 `activeTab`/`scripting`、`storage` 等即可；若评论生成与识别走 Background 调 LLM，已具备网络权限。
2. **性能**：评论生成与识别可加 loading；批量提交时间隔与节奏可配置或固定（如 3–5 秒/站），避免对目标站造成压力。
3. **安全与合规**：不存储评论原文到云端；LLM 仅接收页面 title/description 与表单结构，不发送整页 HTML；用户自行配置 API Key。

## 七、实现范围与优先级

| 优先级 | 内容 | 说明 |
|--------|------|------|
| P0 | Popup 增加 Blog 评论 Tab | 切换后仅显示评论相关 UI |

| P0 | 评论表单 AI 识别与填充 | 4 个标准字段 + 提交按钮，多语言靠 AI |
| P0 | 防 Spam 检测与暂停逻辑 | 检测到则只填充不点提交，并提示 |
| P0 | 一键「生成评论并填充」单页流程 | 生成→识别→填充→（无验证时）点击提交 |

## 八、测试验证建议

1. **第一阶段：单页 Blog 评论**
   - 在 2–3 个不同站点（含英文、一种非英文如捷克语）的博客评论页，验证：
     - 切换 Popup 到 Blog 评论 Tab 后，能正确识别评论表单并显示状态；
     - 「生成评论并填充」能生成合理评论并填满 Comment/Name/Email/Website；
     - 无验证时能自动点击提交；有验证时仅填充并提示。
   - **验证环节**：提交后（或用户手动提交后点击「验证本次提交」）重新读取页面，在页面中能找到指向当前站点 URL 且可点击的链接，即显示「验证成功」。
2. **第二阶段：批量提交**
   - 在列表中加入 2–3 个 URL（含一个带验证的站点），执行批量提交：
     - 顺序、间隔、每站提交后的验证环节（重新读页、查找本站链接）与结果统计符合预期；
     - 汇总中能区分「验证成功」「需人工验证」「验证未通过」。
3. **用例文档**
   - 在 `doc/2.blog-comment/` 下提供「测试用例」文档，列出具体测试步骤与预期结果，便于回归。

## 九、附录：与导航站模式的对比

| 维度 | 导航站模式 | Blog 评论模式 |
|------|------------|----------------|
| 标准字段 | 网站名称、URL、邮箱、分类、描述、Logo 等 | Comment、Name、Email、Website |
| 内容生成 | 可选「介绍语生成」 | 必选「评论生成」（基于当前页 Metadata） |
| 提交动作 | 可选自动点击提交 | 无验证时自动点击提交；有验证则暂停 |
| 提交后验证 | 无 | 重新读取页面，查找可点击的本站链接，找到即视为成功 |
| 站点列表 | 导航站列表（提交页 URL） | Blog 评论站点列表（博客评论页 URL） |
| 识别 | 同一套 AI/规则框架 | 同一套框架，不同标准字段与 prompt |
