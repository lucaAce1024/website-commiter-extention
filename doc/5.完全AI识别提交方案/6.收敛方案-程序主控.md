# 收敛方案：程序主控（AI 仅评论 + Snapshot 定位 + 程序执行）

## 一、目标与原则

- **收敛 AI 作用范围**：AI 只负责**生成评论内容**（comment）；不依赖 LLM 输出「填哪、点哪」的完整计划。
- **程序主控**：由程序完成「Snapshot 定位 → 元素映射 → 固定顺序执行」，沿用现有定位、填充、勾选、点击逻辑，行为可预期、易排查。
- **新站无缓存**：首次访问新网站时，不依赖站点缓存；通过**多轮弹窗处理** + **当页 Snapshot 启发式匹配**，实现关弹窗、填表单、过人机验证、提交。

---

## 二、角色划分

| 角色 | 职责 | 实现方式 |
|------|------|----------|
| **AI** | 仅生成评论文案（comment） | 沿用现有 `generateBlogComment` 或单次 LLM 调用 |
| **Snapshot** | 抓取页面 DOM，为可交互节点分配 UID，供程序定位 | Content 内 `fullAiTakeSnapshot`，返回 `snapshotResult`（含 idToNode） |
| **程序·定位** | 从 Snapshot 中识别：Name、Email、Website、Comment、提交按钮、必选 checkbox、人机验证框 | 启发式匹配：role + name/placeholder/label 关键词 |
| **程序·执行** | 按固定顺序：fills → checks → clicks，模拟人机输入与点击 | 沿用 `fullAiExecute`（typeIntoElementWithDelay、simulateClick） |
| **多轮弹窗** | 规避 Cookie/隐私弹窗，避免评论区被遮挡 | 多轮（如 3 轮）检测并点击「Accept/同意」等按钮，可启发式或保留一次轻量 LLM 找按钮 |

---

## 三、整体流程

```
1. 多轮弹窗处理（最多 N 轮）
   → 每轮：取 Snapshot（整页）→ 程序或轻量 LLM 识别「关闭」按钮 uid → 点击 → 等待
   → 无弹窗或轮次用尽后进入下一步

2. 表单准备与 Snapshot（表单范围）
   → fullAiPrepareForComment：预滚动、表单检测、formRootSelector
   → fullAiTakeSnapshot(scopeRootSelector)：采集表单内 DOM，得到 snapshotResult

3. 程序内元素映射（无缓存也适用）
   → buildStepsFromSnapshot(snapshotResult, fillData)
   → 启发式：从 idToNode 中按 role + name/placeholder 匹配
     - textbox/combobox：Name / Email / Website / Comment / 人机验证（可选）
     - checkbox：Notify、同意、「我不是机器人」等
     - button/link：Submit / Post Comment / 发布 / 提交
   → 输出 steps：fills（含人机验证值若可程序计算）→ checks → clicks

4. 执行
   → fullAiExecute(steps)：沿用现有填充、勾选、点击逻辑，顺序执行
```

---

## 四、元素映射规则（启发式）

- **Name**：role 为 textbox/combobox，且 name/placeholder/label 含 `name`、`author`、`姓名`、`昵称` 等，取匹配度最高的一项。
- **Email**：含 `email`、`mail`、`邮箱`、`e-mail`。
- **Website**：含 `website`、`url`、`site`、`网址`、`链接`、`homepage`。
- **Comment**：含 `comment`、`message`、`内容`、`评论`、`留言`，或 tagName 为 textarea 且尚未被 Name/Email/Website 占用。
- **提交按钮**：role 为 button 或 link，name 含 `submit`、`post`、`comment`、`发布`、`提交`、`send`、`发表`。
- **必选 checkbox**：role 为 checkbox，name/label 含 `notify`、`agree`、`terms`、`robot`、`机器人`、`同意`、`条款`；若存在则加入 checks，checked=true。
- **人机验证**：name/placeholder 含简单算式（如 `2+3=?`）或 `验证`、`captcha`（仅简单算术时程序解析并填入，否则可跳过或一次最小 LLM 仅返回数字）。

匹配时对 name、placeholder、相邻 StaticText 做小写+去空格后关键词包含判断；同一 slot 取第一个匹配或得分最高者。

---

## 五、多轮弹窗与无缓存新站

- **弹窗处理**：在「取表单 Snapshot」之前，先做 1～3 轮整页 Snapshot，每轮用程序或一次轻量 LLM 判断是否存在「Accept/同意/Allow」等按钮；若有则点击并等待 1～2s，再下一轮。这样新站首次打开即能关掉隐私弹窗，再进入表单 Snapshot。
- **无缓存**：不依赖站点级缓存；每次任务都用当页 Snapshot + 启发式映射得到 steps，因此新站与老站同一套逻辑。

---

## 六、与现有实现的关系

| 现有 | 收敛后 |
|------|--------|
| 一次性 LLM 规划（fills/checks/clicks 全由 LLM 输出） | 取消；改为程序 buildStepsFromSnapshot |
| fullAiTakeSnapshot | 保留；仍用于弹窗轮次 + 表单范围采集 |
| fullAiExecute(steps) | 保留；仍负责 fill/check/click 执行与模拟人机 |
| runOverlayDismissLoop | 保留；多轮弹窗处理 |
| generateBlogComment / 评论生成 | 保留；AI 仅负责评论内容 |
| formHandler.handleFullAiPrepareForComment | 保留；表单检测与 formRootSelector |

---

## 七、验收要点

1. AI 仅参与评论生成（与可选的一次性弹窗按钮识别）；不输出完整操作计划。
2. 新站无缓存时，多轮弹窗后能取到表单 Snapshot，程序能映射出 Name/Email/Website/Comment/提交/必要 checkbox。
3. 执行顺序固定、由程序控制；执行层沿用现有定位、填充、勾选逻辑，可复现、易排错。
4. 简单人机验证（如算术）可由程序解析并填入，或最小 LLM 仅返回数字，不扩大 AI 范围。
